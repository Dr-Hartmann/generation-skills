# Формат приложения и итоговый результат

## Требуемый результат

Создай один самостоятельный HTML-файл. В нём должны находиться:

- HTML-разметка;
- пользовательские стили внутри `<style>`;
- JavaScript-логика внутри `<script>`.

Не создавай отдельные CSS- и JS-файлы. Не требуй сборщика, npm, локального сервера или предварительной компиляции.

## Подключение библиотек

Внешние библиотеки разрешено подключать через CDN, если они действительно нужны для задачи. Параметр viewport задан в реестре `FMT-02`, правила подключения CDN — в `FMT-03`.

Внешние классические скрипты размещай в `<head>` с `defer`. Встроенный inline-скрипт не снабжай `defer`: размещай его перед закрывающим `</body>` либо запускай после готовности DOM.

Не подключай библиотеку только ради простого эффекта, который можно реализовать стандартными средствами браузера.

## Запуск из файла

Приложение должно запускаться при открытии HTML-файла в браузере. Поэтому:

- не используй локальный сервер как обязательное условие;
- не загружай обязательные локальные данные через `fetch`, XHR или динамический импорт;
- не рассчитывай на серверные API;
- не используй сборочные пути, которые существуют только в среде разработки.

Если подключена библиотека через CDN, для её загрузки требуется доступ к сети. Не заявляй об офлайн-работе, если внешняя зависимость не встроена в HTML.

## Самодостаточность

Все данные, необходимые для демонстрации интерактива, должны быть определены внутри HTML. Исключение — необязательные внешние библиотеки, загружаемые с CDN.

Приложение должно корректно обработать отсутствие необязательной библиотеки: либо использовать нативную реализацию, либо вывести понятную ошибку в консоль, не оставляя интерфейс в бесконечном состоянии загрузки.

## Итоговая передача

В ответ на запрос о создании приложения передавай готовый HTML-файл. Не добавляй к самому HTML пояснительные тексты, инструкции по запуску или комментарии. Пояснение в сообщении чата не заменяет HTML-файл.
